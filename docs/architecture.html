CODE INTELLIGENCE · PRD → EXECUTION PLAN

Graphify Architecture

A polyglot, multi-service code-intelligence system. Given a PRD, it finds the affected code, computes a precise blast radius across services — including the edges the compiler can't see (HTTP, schedulers, events, DI) — and grounds an ordered execution plan in the real code graph. Deterministic where a syntactic anchor exists; the LLM to author the rules and bridge the semantic gaps.

The core decision: confidence tiers, not just facts

EXTRACTED · 1.0

Proven from syntax — an import, a call, a decorator binding, a SCIP-resolved reference. Precision consumers filter to this.

INFERRED · 0.55–0.95

A grounded inference — cross-service HTTP match, name-resolved DI, LLM doc edge. Kept with a score; blast radius uses it.

AMBIGUOUS

Uncertain — a path collision fanned to all candidates. Never dropped (demote-not-delete): a probable edge beats a missing one.

This is what separates Graphify from compiler-only tools (Glean, Sourcegraph's SCIP core): they store only what the compiler proves and have zero recall on dynamic / cross-service edges. Graphify keeps them, tiered — because blast radius must not silently miss an affected path.

Why cross-boundary edges matter: entry points

HTTP

calls_service — a consumer's HTTP call matched to a producer endpoint by (method, normalized-path) across services & languages.

Schedules & events

triggers / consumes — a cron or message handler is an entry point the compiler can't see. Blast radius: "what runs this on a timer / an event?"

Dependency injection

injects — a class depends on an injected type. "Changing this type affects the classes that inject it." Name-resolved, INFERRED; SCIP upgrades it.

All four fold onto the tree-sitter AST nodes via reconcile_contract and live in DEFAULT_AFFECTED_RELATIONS, so a single blast_radius query traverses in-process calls and every cross-boundary edge.

Main decision points

Deterministic core, LLM at the edges

tree-sitter + rules for anything with a syntactic anchor (reproducible, free). The LLM only for docs, prose→code, and authoring detection rules — never as the run-time extractor.

Demote, don't delete

Contradicted or unresolved edges are retagged (AMBIGUOUS / raw target), never dropped. Recall consumers keep everything; precision consumers filter. Blast radius is recall-critical.

Extractor, not datastore

Graphify is stateless. Structural edges + semantic vectors persist to commodity Postgres — one store, no separate graph DB, no graph.json to sync.

Merge-on-identity

Every layer (SCIP, contract, schedule, DI) folds onto the canonical tree-sitter node by (path-suffix, name). The AST node stays the anchor; precision layers stamp it.

Derive service from controllers

No gateway/service-registry assumed. Service identity = where the controller lives; match by path against a global catalog. Host resolution only disambiguates collisions.

Pluggable by data

New frameworks are rule rows, not modules. One engine, one reconcile, one blast-radius pass — adding a construct is a relation string + a rule.
